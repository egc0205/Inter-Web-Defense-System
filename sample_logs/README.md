# Overview
There's five different main folders with different types of attacks and being from different datasets
The three network folders being (web_attacks/, ddos/ and portscan/) are from the CIC-IDS2017 which is from a test network company over the span of a week and they tested attacks. I trimmed each set because it was originally a lot of traffic to look through then put it through suricata and zeek in order to get the sample logs.

The other two folders arp_spoofing and email are there because the first dataset didnt have attacks of those types
arp_spoofing is traffic samples from the original dataset with a generated attack and the email folder has emails that come from a phishing collection and the legitimate emails come from Apache's public mailing lists.

# How the logs look
Every log file is one event per line and each line is written in JSON so it's just "field": value pairs. 

# Folder setups
the network folders have the same setup being a connection log (zeek/conn.log), http log (zeek/http.log), dns log (zeek/dns.log), suricata alarms if you want to look at them (suricata_alerts.json), and a file downloads log (zeek/files.log)

Every folder also has a ground_truth.csv which is the answer key so dont use this for anything other than fact checking 

The uid field is the connection's ID, the same uid shows up in all the zeek logs and the ground_truth.csv so you can link everything from one connection together.

Some field names that arent obvious:
id.orig_h / id.orig_p = who started the connection (source IP / port)
id.resp_h / id.resp_p = who it connected to (destination IP / port)
ts = the time, as a Unix timestamp
conn_state = how the connection ended. SF is normal, REJ means it got rejected (port closed), RSTO means the client cut it off

In the network folders the attacker shows up as 172.16.0.1 and the web server getting attacked is 192.168.10.50.

### web_attacks/
Thursday July 6 2017, 9:10 to 10:50 AM. Has SQL injection (12 connections), XSS (637) and someone guessing passwords over and over on the login page (1,407), mixed in with 17,220 normal connections. I only kept 1 out of every 4 normal connections to make it smaller but every attack is in there.

### ddos/
Friday July 7 2017, 3:54 to 4:00 PM. The first 2 minutes are normal and then at 3:56 one machine starts flooding the web server, about 16,000 requests in 4 minutes. 4,777 normal connections.

### portscan/
Friday July 7 2017, about 2:50 to 2:52 PM. One machine knocks on almost 1,000 different ports on the server to see what's open, which is what attackers do before an attack. About 10,900 scan connections and 758 normal ones.

### email/
There's 403 phishing emails and 1,200 legitimate ones, all from 2024. The emails are in emails.jsonl (one email per line).

### arp_spoofing/
The normal traffic is real (Friday July 7 2017, 3:45 to 4:25 PM) but the attack was generated by me since I couldn't find a real one. From 3:50 to 3:55 PM the computer 192.168.10.17 (MAC 00:23:ae:9b:95:67) keeps telling 3 other computers (.5, .8 and .9) that it's the gateway 192.168.10.1 and tells the gateway that it is those 3 computers. That way their traffic goes through it. It does this every 2 seconds which is how the arpspoof tool works, 900 fake messages total. The ARP messages are in arp.log (one message per line).

# Things to know
The ARP attack is generated not recorded
The phishing and legitimate emails come from different places so dont make rules based on stuff that is only different because of that. All the phishing was sent to one person jose@monkey.org the legitimate ones were sent to mailing lists and DMARC is missing on most of the real ones.
There's no IP or DNS spoofing data right now it wasnt easy and i ran out of time so ill take a look at it later
